# LiteDB Native AOT Support - Implementation Roadmap

## Quick Summary

**Goal**: Make LiteDB compatible with .NET Native AOT compilation.

**Status**: Planning Phase

**Estimated Effort**: 16 weeks (4 months)

**Target Version**: LiteDB v6.0 (major version due to potential breaking changes)

---

## Critical AOT Blockers

### 🔴 High Priority Blockers

1. **Expression.Compile() Usage**
   - Location: `Reflection.Expression.cs`
   - Impact: Complete blocker
   - Solution: Source generators

2. **Activator.CreateInstance()**
   - Location: `BsonMapper.Deserialize.cs`, `ShellProgram.cs`
   - Impact: Complete blocker
   - Solution: Factory pattern + source generators

3. **MakeGenericType()**
   - Location: `Reflection.cs`
   - Impact: High
   - Solution: Pre-register generic types or use source generators

### 🟡 Medium Priority Blockers

4. **Type.GetType() String Resolution**
   - Location: `DefaultTypeNameBinder.cs`
   - Impact: Medium
   - Solution: Type registry

5. **Reflection-based Member Access**
   - Location: Throughout mapper system
   - Impact: Medium
   - Solution: Source generators for accessors

**Tasks**:

**Example Generated Code**:
```csharp
[BsonDocument]
public partial class Customer
{
    public int Id { get; set; }
    public string Name { get; set; }
}

// Generated by source generator
partial class Customer
{
    internal static class BsonGeneratedMapper
    {
        public static Customer Create() => new Customer();
        public static object GetId(Customer obj) => obj.Id;
        public static void SetId(Customer obj, object value) => obj.Id = (int)value;
        // ... more getters/setters
    }
}
```

**Deliverables**:

### Phase 3: Mapper Refactoring (Weeks 7-10)
**Goal**: Refactor BsonMapper to use generated code when available

**Tasks**:
- [ ] Create `IBsonMapperStrategy` interface
- [ ] Implement `SourceGeneratedMapperStrategy` (uses generated code)
- [ ] Keep `ReflectionMapperStrategy` (uses current reflection approach)
- [ ] Update `BsonMapper` to auto-detect and use generated mappers
- [ ] Add `BsonMapper.CreateForAOT()` factory method
- [ ] Add `BsonMapper.CreateReflection()` factory method (default)
- [ ] Implement fallback: use reflection if no generated code found
- [ ] Update type resolution with registry pattern

**API Design**:
```csharp
// Option 1: Auto-detection (recommended)
var mapper = BsonMapper.Global; // Auto-detects generated code

// Option 2: Explicit AOT mode
var mapper = BsonMapper.CreateForAOT();
mapper.RegisterType<Customer>(); // Uses generated code

// Option 3: Force reflection mode (for compatibility)
var mapper = BsonMapper.CreateReflection();
```

**Deliverables**:
- BsonMapper works with source-generated types
- Backward compatibility maintained
- Clear API for AOT mode selection

## Technical Design Decisions

### Decision 1: Source Generator vs Manual Factory
**Choice**: Source Generator  
**Reason**: Better developer experience, automatic code generation, compile-time safety

### Decision 2: Breaking Changes vs Backward Compatibility
**Choice**: Backward Compatible (Hybrid Approach)  
**Reason**: Allow gradual migration, don't break existing users

### Decision 3: Required .NET Version
**Choice**: .NET 8.0+ for AOT support, maintain .NET 4.5/netstandard2.0 for non-AOT  
**Reason**: AOT features require modern .NET, but keep compatibility for existing users

### Decision 4: Opt-in vs Opt-out
**Choice**: Opt-in (Add `[BsonDocument]` attribute)  
**Reason**: Clear intent, no breaking changes, users choose when ready

## Migration Guide Preview

### Before (LiteDB v5.x)
```csharp
// Works with reflection (not AOT-compatible)
using(var db = new LiteDatabase("data.db"))
{
    var customers = db.GetCollection<Customer>("customers");
    customers.Insert(new Customer { Name = "John" });
}
```

### After (LiteDB v6.0 - AOT Compatible)
```csharp
// Add attribute to your class
[BsonDocument]
public partial class Customer // Note: must be partial
{
    public int Id { get; set; }
    public string Name { get; set; }
}

// Usage remains the same!
using(var db = new LiteDatabase("data.db"))
{
    var customers = db.GetCollection<Customer>("customers");
    customers.Insert(new Customer { Name = "John" });
}

// Or explicitly use AOT mode
using(var db = new LiteDatabase("data.db"))
{
    db.Mapper = BsonMapper.CreateForAOT();
    db.Mapper.RegisterType<Customer>();
    
    var customers = db.GetCollection<Customer>("customers");
    customers.Insert(new Customer { Name = "John" });
}
```

### Publishing with AOT
```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <PublishAot>true</PublishAot>
  </PropertyGroup>
  
  <ItemGroup>
    <PackageReference Include="LiteDB" Version="6.0.0" />
  </ItemGroup>
</Project>
```

```bash
dotnet publish -r linux-x64 -c Release
# Results in single-file native executable with no .NET runtime required
```

## Open Questions

1. **Should we require .NET 8.0 for all features, or multi-target?**
   - Proposed: Multi-target, AOT support only on .NET 8.0+

2. **How to handle polymorphic types in AOT mode?**
   - Proposed: Explicit type registration required

3. **Should LINQ queries work in AOT mode?**
   - Proposed: Expression-based queries require source generator support (Phase 2 extension)

4. **How to handle custom converters?**
   - Proposed: Require explicit registration with factory delegates
